# X1 — LoRA experiment

## Question

Does a LoRA adapter trained on a Thai open model imitate a person's style better than prompt-only
personas? If yes, Phase 4 (Pro personas) is worth building. If no, stay with prompt-based modes.

Cost target: $0 (Kaggle free GPU + a few dollars of frontier API calls for expansion and judging).

## Design

Per persona, compare three conditions on the same held-out questions:

| Condition | Model | Prompt |
|---|---|---|
| `frontier_prompt_only` | App's current chat model | Full runtime prompt with fixed examples (what the app does today) |
| `typhoon_prompt_only` | Typhoon 2.5 4B, no adapter | Same runtime prompt with fixed examples |
| `lora` | Typhoon 2.5 4B + persona adapter | Short system prompt only, no examples |

`typhoon_prompt_only` vs `lora` isolates the adapter's effect on the same base model.
`frontier_prompt_only` vs `lora` answers the product question.

Base model: `typhoon-ai/typhoon2.5-qwen3-4b` (Qwen3 4B architecture, Thai + English).
Check the model card for license terms before any commercial use.

## Data rules (non-negotiable)

- Only personas of people who gave explicit consent (yourself, friends who agreed in writing/chat).
- Kaggle datasets and notebooks stay **private**. Delete the dataset when the experiment ends.
- Held-out examples are **real** examples only and are never shown to the expansion step.
- Remove passwords, keys, phone numbers, addresses, and third parties' names before export.

## Dataset per persona

| Split | Source | Size |
|---|---|---|
| `heldout` | real examples | 5–10 (20% of real, min 5) |
| `train` | remaining real examples | 20–50 |
| `train` | synthetic expansion from train split | 200–400 pairs |

Synthetic pairs are generated by the frontier model from **train** examples only, using the prompt
below, then deduplicated. Spot-check 20 of them with the persona owner before training.

### prompts/style_expand.md (v1)

```text
Below are real answers written by one person, with their style card. Write {{n}} NEW question and
answer pairs that this person could plausibly receive and answer.

Requirements:
- Cover these question shapes evenly: {{shapes}}
- Topics: varied, within these domains: {{domains}}
- Answers must copy the style exactly: length, structure, formatting, Thai/English mix, particles
- Do not reuse any sentence, distinctive phrase, fact, name, or topic from the real examples
- Questions should sound like real people asking (Thai, English, or mixed, matching the examples)

<style_card>{{style_card_json}}</style_card>
<examples>{{train_examples}}</examples>

Return only JSON: {"pairs": [{"shape": "...", "question": "...", "answer": "..."}]}
```

Generate in batches of 20 and deduplicate by question similarity.

## File formats

### Export (app → Kaggle): `persona_{id}.jsonl`

First line is metadata, then one line per example.

```json
{"type": "meta", "persona_id": "p_123", "version_id": "v_456", "display_name": "Nat",
 "lora_system_prompt": "You are the AI version of Nat.",
 "runtime_system_prompt": "<full runtime prompt with style card and fixed examples>"}
{"type": "example", "id": "e_1", "split": "train", "source": "real", "shape": "comparison",
 "question": "Kafka vs MQTT", "answer": "คล้ายกัน แต่ MQTT เบากว่า ..."}
{"type": "example", "id": "e_2", "split": "train", "source": "synthetic", "shape": "how_to",
 "question": "...", "answer": "..."}
{"type": "example", "id": "e_9", "split": "heldout", "source": "real", "shape": "definition",
 "question": "...", "answer": "...", "baseline_answer": "<frontier_prompt_only answer>"}
```

### Results (Kaggle → app): `results_{persona_id}.jsonl`

```json
{"example_id": "e_9", "condition": "lora", "answer": "..."}
{"example_id": "e_9", "condition": "typhoon_prompt_only", "answer": "..."}
```

`scripts/judge_experiment.py` adds `frontier_prompt_only` from `baseline_answer`, judges all three
against the real held-out answer with `prompts/judge.md`, and writes the report.

## Steps

1. In the app repo: `scripts/expand_dataset.py` → `scripts/export_lora_dataset.py`
   (`--persona-ids ... --consent-confirmed`).
2. Kaggle: create a **private** dataset and upload the JSONL files.
3. Kaggle: import `experiments/lora/persona_lora_kaggle.ipynb`. Settings: Accelerator = GPU T4,
   Internet = on. Add the dataset. Set `PERSONA_FILE` in the config cell. Run all.
4. Download `results_{persona_id}.jsonl` (and optionally the adapter zip) from `/kaggle/working`.
5. In the app repo: `scripts/judge_experiment.py --export ... --results ...`.
6. Repeat for 5–10 personas. One persona per notebook run; restart the session between runs.
7. Blind human check: for 2–3 personas, mix real, `lora`, and `frontier_prompt_only` answers and
   ask the owner's friends which ones are real.

Kaggle's free GPU quota is limited per week (about 30 hours at the time of writing); each run should
take well under an hour for a 4B model with a few hundred pairs.

## Starting hyperparameters

LoRA rank 16, alpha 16, dropout 0, all attention + MLP projections, 4-bit base,
3 epochs, learning rate 2e-4, effective batch size 8, max sequence length 2048,
train on assistant responses only. If the adapter copies training answers verbatim, reduce epochs
to 1–2 or rank to 8.

## Decision rule

Judge scores are 1–10 (`overall`).

- **Go to Phase 4** if `lora` beats `frontier_prompt_only` by ≥ 0.5 on average in at least 4 of 5
  personas **and** the blind human check agrees (friends pick `lora` as real at least as often).
- **Maybe** if `lora` ≈ `frontier_prompt_only` but `typhoon_prompt_only` is much worse: adapters
  could power a cheap free tier (Phase 3) rather than a premium tier.
- **Stop** otherwise. Record why and keep prompt-based modes.

Also check for memorization: if any `lora` answer shares long passages with a training answer
(character 8-gram overlap > 0.35), note it — public adapters would then need stricter data rules.

## Serving caveat (before Phase 4)

An adapter only works with the exact base model it was trained on. Before committing, confirm a
serving option for `typhoon2.5-qwen3-4b` + adapters: a multi-LoRA host that supports this base, or
vLLM with LoRA on rented GPUs. If only standard Qwen3 is supported serverlessly, rerun X1 with a
Qwen3 base and compare.
